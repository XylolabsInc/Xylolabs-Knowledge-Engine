# 구매 품의서

물건을 사기 전(또는 산 직후)에 올리는 `구매 품의서` 규칙이다. 구독과 사용료도 결제마다 품의를 올린다. 공통 규칙은 `approval` 을 함께 읽는다.

## 순서

| 단계 | 도구 | 하는 일 |
|---|---|---|
| 1 | `draft_purchase` | 초안을 만들고 검증한다. 칸별 값과 고칠 것을 돌려준다. 다우오피스에는 올리지 않는다 |
| 2 | `capture_quote` | 상품 페이지를 찍어 견적서 대신 붙인다. 찍은 사진을 사람에게 보여 준다 |
| 3 | `submit_purchase` | 미리보기(칸별 값, 결재선, 견적 사진)를 만든다. 사람이 승인하면 상신하고 서버 문서를 칸별로 대조한다 |

- 초안에는 판(revision)이 있다. 초안이나 견적이 바뀌면 판이 올라간다. `submit_purchase` 에는 마지막으로 받은 판을 넘긴다.
- 미리보기를 보여 준 뒤 초안을 고치면 그 미리보기의 승인은 아무것도 올리지 않는다. 고친 뒤 미리보기를 다시 만든다.
- 검증 오류가 하나라도 있으면 올리지 않는다. 오류는 전부 사람에게 보여 주고 고친다.
- 목록은 `list_purchases` 로 본다. 다우오피스의 실제 결재 상태는 `read_document` 로 본다.

## 칸

| 칸 | 규칙 | 예 |
|---|---|---|
| 제목 | 문서가 하는 일에 맞춘다(아래) | `테스트 카메라 구매의 건` |
| 예산 | 회사 설정의 예산. 사업비면 프로젝트, 세부 과제가 있는 프로젝트는 세부 과제도 고른다 | `프로젝트 사업비` / `테스트과제` / `테스트세부` |
| 구매품명 | **수량을 붙인다** | `테스트 카메라 / 1개`, `테스트 케이블 외 2종 / 총 5개` |
| 업체명 | **판매자**, 플랫폼은 괄호 | `테스트상점 (알리익스프레스)` |
| 구입수량 | 품명의 수량을 더한다. `qty` 로 따로 정할 수 있다 | `5개` |
| 구입일자 | **카드 결제일**. 결제 전이면 구입 예정일. 요일은 자동으로 붙는다 | `2026-01-15(목)` |
| 구입목적 | **대상과 용도**. 품명을 되풀이하지 않는다 | 아래 |
| 총금액 | 총금액, 공급가액, 부가세액. 국내는 총액의 10/110 이 부가세, 해외는 0. 영수증에 부가세가 따로 적혀 있으면 `vat` | `110,000` / `100,000` / `10,000` |
| 지급요청일 | `당월` 또는 `익월`. 카드면 기본 `당월` | |
| 지급방법 | 카드면 카드사와 뒤 네 자리. 카드 뒷자리를 주면 회사 설정의 카드에서 예산, 프로젝트, 카드사를 채운다 | |
| 지급계좌, 예금주 | 카드 결제면 `해당없음` 이 자동으로 들어간다 | |
| 기타(링크) | 첫 줄에 상품 링크. 구성과 단가, 할인, 배송비, 주문번호를 항목으로 | 아래 |

옛 양식(배송일자 칸이 있던 양식)으로 올린 문서를 고칠 때는 배송일자(`deliveryDate`)가 필요하다. 새 문서는 새 양식으로 올라간다.

### 제목 끝

| 무엇 | 끝 | 예 |
|---|---|---|
| 물건 | `구매의 건` | `테스트 충전기 구매의 건` |
| 구독 | `구독의 건` | `테스트 서비스 구독의 건 (2026-01-15 결제분)` |
| 도메인, 라이선스 연장 | `갱신의 건` | `테스트 도메인 갱신의 건` |
| 사용량 청구 | `지출의 건` | `테스트 클라우드 2026년 1월 사용료 지출의 건` |

품목 가짓수는 `종` 으로 센다. `외 6종 구매의 건` 이고 `외 6건 구매의 건` 이 아니다(`건` 이 두 번 나와 읽기 나쁘다).

### 수량 단위

| 무엇 | 단위 | 예 |
|---|---|---|
| 물건 | `개`, `대`, `세트`, `개입` | `… 6개입 / 1세트` |
| 여러 가지 | `총 N개` | `… 외 3종 / 총 5개` |
| 월 구독 | `개월` | `… 월 이용권 / 1개월` |
| 계정 구독 | `계정` | `… / 1계정` |
| 크레딧 | 외화 금액 | `… 크레딧 / USD 50.00` |
| 사용료 | `건` | `… 이용료 2026년 1월분 / 1건` |

검증은 이 단위만 안다. `100개입 / 1봉` 은 거부되니 `100개입 / 1개` 로 쓴다.

### 업체명은 판매자다

네이버페이, 카카오페이, 쿠페이는 결제수단이라 적지 않는다. 판매자 이름은 상품 페이지의 스토어 이름에 있다. 카드를 결제한 쪽이 판매자다. 제조사 직영몰이 아니라 대리점이 카드를 결제했으면 그 대리점을 쓴다.

### 구입목적

어디에서 무엇을 하려고 쓰는지 한 줄로 쓴다. 이런 꼴이다.

- `온실 작물 생육 원격 관찰` (카메라)
- `실험실 시료 무게 측정` (전자저울)
- `현장 장비 원격 전원 제어` (스마트 플러그)

품명의 낱말을 되풀이하면 검증이 거부한다. **목적은 지어내지 않는다.** 순서는 이렇다.

1. 사람이 말한 것(묶음으로 정해 준 것 포함)
2. 같은 종류 물건으로 통과한 예전 품의의 목적(그렇게 했으면 올린 뒤 그 목록을 사람에게 알린다)
3. 그래도 모르면 묻는다

세부 과제도 지어내지 않는다. 물건이 어느 세부 과제에 속하는지 모르면 묻는다.

### 기타는 문장이 아니라 항목이다

한 줄에 사실 하나, 명사형으로 끝낸다. `…다`, `…요` 로 끝나는 줄은 거부된다.

| 나쁨 | 좋음 |
|---|---|
| `두 건이 한 번에 결제되어 한 건으로 작성한다` | `2026-01-15 카드 승인 12,000원 한 줄` |
| `배송비 0` | `배송비 없음` |
| `… USD 12.30 — https://…` | 두 줄로 나눈다: 가격이 붙은 품목, 그다음 링크 |

해외에서 직접 산 전파 송수신 기기(조종기, 수신기, 라우터, 프리앰프 등)는 통관 때 적합성평가 면제 사유서를 낸다. 기타에 이 줄을 넣는다: `전파법 요건 면제 사유서 제출 대상, 해외 직접구매 전파기기`. 국내 판매자에게 산 것과 전파 기기가 아닌 부품에는 넣지 않는다.

## 금액과 환율

| 경우 | 넣는 칸 | 금액 |
|---|---|---|
| 원화 결제 | `amount` | 쿠폰 적용 뒤 실제 결제(예정)액 |
| 외화, 아직 결제 전 | `usd` | 초안을 만들 때 받은 하나은행 매매기준율로 환산 |
| 외화, 카드 결제 뒤 | `usd` + `paidKrw` + `paidAt` | **카드 승인액 그대로** |

- 환율은 하루에도 여러 번 바뀐다. 초안을 처음 저장할 때 받은 값을 초안에 고정하고, 미리보기와 상신이 같은 값을 쓴다. 다시 받으려면 `refreshFx`.
- **카드로 결제한 건은 환산하지 않는다.** 카드사 적용환율은 고시 기준율과 달라 환산하면 카드 대장과 어긋난다. 적용환율은 승인액을 외화로 나누어 기타 칸에 자동으로 적는다. 적용환율이 1,000원에서 1,800원을 벗어나면 금액 짝이 틀린 것으로 보고 거부한다.
- 카드 대장에 아직 안 올라온 외화 결제는 승인액이 올라온 뒤 `paidKrw` 를 넣어 올린다. 국내 결제는 대장에 올라오기 전에 올려도 된다(결제일과 영수증 총액).
- 카드 한 줄에 주문 여럿이 묶였으면 품의도 한 건으로 묶는다. 다만 알리익스프레스는 **주문 영수증마다 품의를 따로** 쓰고, 카드 승인액을 주문 USD 비율로 나누어 품의마다 `paidKrw` 에 넣는다(나눈 합이 승인액과 정확히 같게).
- 회사가 정한 최소 금액보다 작은 결제는 경고가 나온다. 장바구니에 모아 한 번에 결제하는 것이 회계 안내다. 이미 결제한 건은 막지 않는다.

## 견적 캡처

- **판매 페이지 캡처는 필수다.** 없으면 올리지 않는다. 구매 전 문서라 **영수증과 주문내역은 붙이지 않는다.** 주문 상세, 영수증 페이지와 그런 이름의 파일은 거부된다.
- `expect` 에는 페이지에 반드시 있어야 할 판매자 이름이나 상품명을 넣는다. 같은 상품을 여러 곳이 판다. 주문한 판매자의 페이지가 아니면 찍지 않는다.
- `options` 에 주문한 옵션을 넣는다. 기본 옵션이 찍히면 주문과 다른 사진이 된다.
- 캡처는 로그인하지 않은 빈 브라우저에서 찍는다. 로그인 화면, 캡차, 차단 화면, 상품이 없는 화면, 가리는 팝업이면 저장하지 않고 이유를 알린다. 캡차는 자동으로 풀지 않는다.
- 찍은 사진은 사람에게 보여 준다. 판매자, 상품명, 옵션, 가격, 통화, 가림을 본다. 미리보기에서 사람이 사진을 보고 승인하는 것이 눈 검사다. 미리보기 뒤에 견적이 바뀌면 올리지 않는다.

### 막히는 사이트

| 사이트 | 대신 할 것 |
|---|---|
| 쿠팡 | 다나와 검색 페이지(`https://search.danawa.com/dsearch.php?query=상품명`). 주문한 상품이 목록에 보여야 한다. `expect` 는 검색어가 아니라 상품 이름 |
| 네이버 스마트스토어 | 제조사나 공식 판매처의 상품 소개 페이지 |
| 아마존 | 그 상품이 나오는 아마존 검색 결과 페이지 |
| 판매가 끝난 상품 | 예전에 찍은 같은 상품 화면을 사람이 첨부로 보낸다 |

판매 페이지를 찍을 수 없으면 대략적인 참고 화면이면 된다. 캡처는 주문의 증거가 아니라 참고 자료다. 그때는 실제 판매처 주소, 옵션, 금액을 기타 칸에 적는다. 한 캡처에 오래 매달리지 않고, 봇 검사를 우회하지 않는다. 사람이 직접 찍은 화면을 첨부해 `url` 없이 `capture_quote` 를 부르면 그 화면을 견적으로 붙인다.

구독과 사용료는 가격 페이지를 그대로 붙인다. 금액은 기타 칸의 인보이스 번호와 청구 기간이 받친다.

## 결재선

결재선은 회사 설정(`lines.purchase`)대로 도구가 넣는다. 기본은 사업비 결재선이다: 기안, 합의 과제 담당자, (설정한 금액 이상이면) 합의 CFO, 결재 대표. 양식의 기본 결재선은 비우고 다시 넣는다. 사업비가 아닌 예산(운영자금 등)은 정해진 규칙이 없어 도구가 멈춘다. 결재선을 사람에게 묻는다.

## 고치기와 다시 올리기

- **fix**: 이미 올린 품의를 고친다. 진행중이고 결재자가 아직 처리하지 않았으면 상신취소하고 같은 문서를 고쳐 다시 올린다. 결재자가 처리했으면 멈춘다. 먼저 `draft_purchase` 로 칸을 고친 뒤 `submit_purchase` 에 `fix: true`.
- **refile**: 최종 결재자(대표)가 빠진 옛 문서를 새 결재선으로 다시 올린다. 옛 문서가 진행중이고 상신취소가 되면 같은 문서로, 아니면 새 문서로 올리고 결재가 끝난 옛 문서를 관련문서로 연결한다. 옛 문서에 이미 최종 결재자가 있으면 거부한다. 옛 양식 품의는 세부 과제와 구입일자(카드 승인일)가 필요하다. 세부 과제는 사람에게 묻는다.
- 상신취소한 문서에는 예전 첨부가 남는다. 도구가 목록에 없는 첨부를 지우고 넘치는 첨부가 있으면 올리지 않는다.

## 확인

올리기 전에 화면에 채운 값을 다시 읽어 대조하고, 올린 뒤 서버 문서를 칸별로 읽어 대조한다(제목, 모든 칸, 첨부 이름, 상태 `진행중`, 결재선). 하나라도 다르면 실패로 알린다. 상태가 `진행중` 이라는 것만으로 성공이라고 하지 않는다.

## 품의가 필요 없는 결제

- 식대, 주유, 철도, 주차, 숙박 같은 출장과 현장 경비(경비청구로 간다)
- 환불, 취소 쌍
- 다른 사람이 품의와 청구를 맡는 결제
- 회사가 품의를 받기 시작한 날 전의 결제

구독과 사용료는 품의가 필요하다. 결제 한 건마다 품의, 인보이스를 붙인 검수조서, 지출결의를 따로 올린다.

## 시리얼 번호

사람이 알려 준 시리얼 번호만 초안의 `serials` 에 적는다. 수량이 여럿이면 알려 준 순서대로 적는다. 시리얼 관리 대상이 아니라고 하면 `noSerials`. 번호는 지어내지 않는다.
