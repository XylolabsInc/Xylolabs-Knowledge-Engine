# 법인카드 지출결의

`file_expense_claim` 으로 올린다. 카드 한 장, 한 달, 사용용도 하나가 문서 하나다. 문서 공통 규칙은 `approval`.

## 언제 올리는가

- **기간은 한국 시간 기준 한 달, 1일부터 말일까지다.** 회계는 카드 명세서와 문서 금액을 맞춘다. 달을 넘기거나 일부만 올리지 않는다. 날짜는 카드 대장의 한국 시간 날짜로 자른다.
- **그 달이 끝나고 영수증과 품의가 갖춰진 뒤 다음 달 초에 올린다.** 끝나지 않은 달은 도구가 막는다. 먼저 올리면 그 뒤 결제를 같은 문서에 넣을 수 없다.
- **카드 대장은 영업일 2-3일 늦게 올라온다.** 달이 끝난 직후에는 마지막 며칠 결제가 아직 없을 수 있다. 며칠 기다렸다 올린다.
- **한 달을 사용용도별 문서로 나눈다.** `purpose` 없이 부르면 사용용도별 묶음을 알려 준다. 하나씩 올린다.
- **같은 달, 같은 사용용도의 두 번째 문서는 만들지 않는다.** 이미 올린 달에 결제가 더 나오면 보충 문서를 올리지 말고 회계에 처리 방법을 묻는다.

## 어떤 결제가 들어가는가

| 결제 | 처리 |
|---|---|
| 영수증이 있는 결제 | 영수증을 붙인다. 인보이스와 영수증처럼 같은 결제의 문서가 둘이면 둘 다 붙인다 |
| 출장 경비 (주유, 철도, 식대, 주차, 택시, 숙박) | 결제일이 기록된 출장 기간에 들면 영수증 없이 `<출장지> 출장 유류비` 처럼 넣는다 |
| 구매 품의가 올라간 결제 | 품의 제목을 상세로 쓴다 |
| 사람이 그대로 넣으라고 한 결제 | 사람이 정한 상세와 사용용도로 넣는다 |
| 다른 사람이 청구하는 결제 | 넣지 않는다. 명세서 대조에 `다른 사람 몫` 으로 보인다 |
| 취소 쌍(같은 가맹점, 같은 금액의 +/−), 0원, 사람이 확인한 환불 | 넣지 않는다. 명세서 대조에 `취소`, `환불` 로 보인다 |
| 말일 결제가 다음 달 초에 취소된 것 | 그 달에 넣지 않는다. 다음 달에는 그 −금액 행이 앞 달 결제의 취소로 보인다 |
| 짝이 없는 음수 행, 이미 청구한 결제의 취소 | 멈추고 목록을 준다. 지출결의 행으로 넣지 않는다. 회계에 처리 방법을 묻고 `notes` 의 `exclude` 와 `reason` 으로 남긴다 |
| 이미 청구한 행 | 넣지 않는다. 문서가 붙었거나 결재가 시작된 행이다 |

- 숙박과 기차표는 출장 전에 사서 결제일이 출장 기간 밖이다. 사람이 어느 출장 것인지 확인한 것만 잇는다. 다른 사람 출장의 표를 내 출장으로 넣지 않는다.
- 같은 날 출장이 둘이면 어느 쪽 비용인지 묻는다.
- `작성중` 은 사용용도만 저장된 상태라 아직 청구 전이다.

## 설명되지 않는 결제

- 도구가 목록을 주고 멈춘다. 가까운 출장에 끼워 넣거나 품목을 지어내지 않는다.
- 결제마다 무엇이었는지 사람에게 묻고 `notes` 로 넣는다. 넣을 결제는 `detail`(상세 사용용도)과 `purpose`(사용용도), 뺄 결제는 `exclude` 와 `reason`.
- 메모는 상신이 끝나면 저장돼 같은 결제에 다시 쓰인다. 다른 사용용도의 문서를 올릴 때 다시 적지 않아도 된다.
- 문서 합계는 그 달 명세서와 맞아야 한다. 설명되지 않은 결제를 조용히 빼지 않는다.

## 사용용도와 상세

- 영수증 비목의 기본 대응은 `재료비` → 재료비, `클라우드구독료`, `소프트웨어` → 수수료비용, `비품` → 소모품비, `사무용품` → 사무용품이다. 회사 설정 `purposeMap` 이 덮는다.
- 출장 경비의 기본 사용용도는 주유 → 차량유지비, 철도와 택시 → 출장교통비, 식대 → 식대, 음료, 주차 → 주차료, 숙박 → 여비교통비다. 설정의 `{ "category": "주유", "purpose": "<사용용도>" }` 처럼 종류 이름으로 덮는다.
- **사용용도 코드는 다우오피스 목록에서 이름으로 찾는다.** 목록에 없으면 도구가 멈춘다. 다른 사용용도로 바꿔 올리지 않는다. 관리자(회계)에게 추가를 요청하거나, 사람이 대체 사용용도를 정하면 회사 설정에 넣는다.
- 모르는 비목은 묻는다. 장비로 잡을지 재료로 잡을지는 사람이 정한다.
- 상세는 승인된 구매 품의 제목에서 가져온다(`… 구매의 건` → `… 구매`). 한 결제에 품의가 여럿이면 `<첫 품목> 외 N종 구매` 로 쓴다.
- 상세도 결재자가 읽는 문장이다. 명사구로 쓰고 `approval` 의 문장 규칙을 따른다. 도구가 기계로 잡을 수 있는 것은 막는다.

## 제목

```
YYYY년 M월 (<카드 뒤 4자리>/<부서 코드>/<명의자>) 법인카드 지출의 건 (<사용용도>)
```

예: `2026년 3월 (1234/rnd/홍길동) 법인카드 지출의 건 (재료비)`. 달은 청구하는 달이고 앞자리 0 을 붙이지 않는다. 부서 코드는 조직도의 코드를 그대로 쓴다. 제목을 비우면 양식 이름이 들어가 회계가 되돌린다.

## 문서 연결

- 행마다 구매 품의서와 검수조서를 관련문서로 연결한다. 회계가 카드 결제와 품의를 이을 수 있어야 한다.
- 결재가 끝난 문서만 연결할 수 있다. 진행중인 것이 있으면 도구가 멈춘다. 결재가 끝난 뒤 올리는 것이 원칙이다.
- 사람이 정하면 `linkDone`(끝난 것만 연결하고 나머지는 기안의견에 적는다) 또는 `withoutLinks`(회계와 합의했을 때만, 모두 기안의견에 적는다)를 쓴다.
- 검수 사진은 지출결의를 올린 뒤 그 문서에 댓글로 붙인다.

## 결재선

- 회사 설정 `lines.claim` 을 따른다. 기본은 대표 결재다.
- 양식 기본 결재선에 결재자가 이미 들어 있어 추가만 하면 한 사람이 두 번 결재하게 된다. 도구가 결재선을 비우고 순서대로 넣은 뒤 이름, 타입, 순서를 대조한다.
- 결재자가 없으면 상신이 곧 완료 처리다. 도구가 그 경고 창을 보면 멈춘다.

## 명세서 대조

미리보기에 `이 달 카드 내역 = 이미 청구 + 이번 문서 + 다른 사용용도 + 다른 사람 몫 + 뺀 결제 + 취소 + 환불` 이 나온다. 음수 행, 취소 짝, 환불까지 이 달 대장의 모든 행을 더하므로 왼쪽은 대장 합과 같다. 설명되지 않은 결제가 남아 있으면 올라가지 않는다.

이미 청구한 결제가 다음 달에 취소됐으면 미리보기에 `주의` 로 나온다. 다음 달 지출결의를 올릴 때 회계와 맞춘다.

## 올린 뒤

- **승인하면 미리보기에서 본 그대로만 올린다.** 그사이 카드 대장에 결제가 늘거나, 품의가 결재돼 연결이 바뀌거나, 영수증 파일이 바뀌면 올리지 않고 미리보기를 다시 만든다.
- 도구가 서버 문서를 다시 읽어 상태(진행중), 제목, 첨부 수, 연결을 대조하고, 카드 대장에서 그 문서에 묶인 행 수와 합계가 이번 문서와 같은지 본다. 상신 직후에는 상태가 비어 있을 수 있어 90초까지 기다린다. 다르면 실패로 알린다.
- 기안의견 창의 `결재요청` 을 누른 뒤에 멈추면 올라갔는지 모른다. 도구는 "확인하지 못했다" 고 알린다. 다시 올리기 전에 다우오피스에서 그 문서의 상태를 확인한다.
- 앞선 시도가 문서를 만들고 멈추면 카드 행이 임시저장 문서에 묶여 남는다. 다음 미리보기가 그 문서 ID 를 알려 주며 멈춘다. 그 문서를 열어 확인하고, 지우거나 상신한 뒤 다시 요청한다.
- 잘못 올렸으면 결재자가 처리하기 전에 `withdraw_document` 로 상신취소한다. 상신취소하면 카드 행의 문서 연결이 풀린다. 그 임시저장 문서를 다시 올리지 말고 지출결의를 새로 만든다. 남은 임시저장 문서는 사람에게 물어 지운다.
- 결재가 끝난 문서는 고칠 수 없다. 정정은 댓글로 남기는데 결재선에 알림이 가므로 문구를 사람에게 먼저 보여 준다.
- 결재가 끝난 옛 청구의 행은 경비 화면에 나오지 않아 다시 묶을 수 없다. 회계가 반려해야 다시 올릴 수 있다.
